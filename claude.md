# Football Broadcast Dashboard — Spec v1

*(Scope has since expanded beyond football — see the MLB and Fights sections near the end. The name/title here is legacy; the page itself now has a sport-neutral header ("Broadcast Dashboard") and a Football/MLB/Fights switcher.)*

## Purpose
Personal dashboard showing upcoming football matches (next ~7 days) across major European and South American leagues and cups, with kickoff time (local + UK), team/competition logos, and which channels are broadcasting — limited to UK and English-speaking channels plus local channels in the countries the user actually watches from (starting with Brazil, Argentina, Mexico).

## Audience
Single user. Not public, not monetized. May expand scope later, but v1 decisions (esp. broadcast data sourcing) assume personal, non-commercial use.

**The owner watches via a multi-market channel service** (stated 2026-08-11): thousands of channels across markets. Practical consequence for every vertical: any listed channel in any market is actionable — geo-restriction notes in this doc describe the networks' own distribution, not what the owner can watch. When deciding what channels/replays to surface, favor completeness across markets over market-filtering.

## In scope (v1)
- Top European leagues: Premier League, La Liga, Bundesliga, Serie A, Ligue 1
- Top South American leagues: Brasileirão, Argentine Primera División (+ others as needed)
- Cups/competitions: Champions League, Europa League, Copa Libertadores, Copa Sudamericana, Copa do Brasil, domestic cups (FA Cup, Copa del Rey, etc. — confirm list)
- Broadcast countries: UK + English-speaking international, Brazil, Argentina, Mexico
- 7-day forward-looking view

## Out of scope (v1)
- Worldwide broadcast coverage (every country)
- Live scores / in-match stats — except a narrow, deliberate exception: the final score of a completed cup-tie leg 1 is stored/shown alongside its scheduled leg 2, to give two-legged ties context. No live/in-progress scores, no stats beyond that single leg-1 result.
- Betting odds
- User accounts, sharing, multi-user features
- Real-time updates (daily refresh is enough)

## Data sources

**Fixtures + logos**
- Sportmonks or API-Football (decide tier once exact competition count is confirmed — likely Sportmonks Starter/Growth)
- Source of truth for: match existence, teams, competition, kickoff time (UTC)

**Broadcast — UK**
- Static, manually maintained table per competition (single-rightsholder pattern: e.g. CL → TNT Sports, PL → Sky/TNT)
- Updated a few times a season, not per-match

**Broadcast — Brazil, Argentina, Mexico**
- Targeted scraper per country against a confirmed aggregator source:
  - Brazil: futebolnatv.com.br
  - Argentina: futbolenvivoargentina.com
  - Mexico: futbolenvivomexico.com
- Note: ARG/MX sites appear to share a platform template — worth checking if the scraper pattern generalizes
- Never source of truth for match existence/time — only supplies the channel field
- Runs daily; re-checks as matchday approaches since channel confirmations often land 2–3 days out, not a full week

## Matching logic (core risk — validate first)
Join scraped channel data to API fixture data via team names + kickoff time window (tolerance for a few minutes' drift between sources). Needs:
- Team name normalization (accents, abbreviations, aliases)
- Fuzzy match, not exact string match
- Graceful "no match found" state (still show the fixture, just no channel yet)

## Failure handling
- If a scraper breaks (layout change, blocked request): fixture still displays, channel field shows blank/TBC — never let one broken source take down the page
- Log match failures for periodic review, not real-time alerting (personal tool, low stakes)

## Time display
- Match's own local kickoff time + UK-equivalent time, side by side
- Confirm assumption: "local" = venue-local kickoff time, not user's location

## Legal/practical hygiene
- Check robots.txt / ToS per scraped source before automating
- **Which robots.txt group actually binds this project (corrected 2026-08-15).** The scraper is an ordinary automated client running in the user's own GitHub Actions — it is **not** ClaudeBot, Claude-Web, anthropic-ai or GPTBot, which are the vendors' own web crawlers. So the group that governs it is **`User-agent: *`** (or one naming its actual UA), and that group's Disallow list must be honoured exactly, `Crawl-delay` included. An AI-crawler block on its own does **not** put a site off-limits. The user, 2026-08-15: *"They are disallowing you, not me or our app."*
  - This corrects an earlier over-strict rule that removed **fulltv.com.ar** and rejected **tvguia.es** purely for naming ClaudeBot/anthropic-ai. Both were re-read in full: tvguia.es's `*` group blocks only `/admin/`, `/search/`, `/user/*`, `/core/`, `/profiles/` and `/program/detail-ajax/`, leaving the guide pages open; fulltv.com.ar's `*` group blocks a specific list (`/programacion.php`, `/*canal.php`, the `.swf` players) that does **not** include the `/tv-vivo-deportes/canal-*.htm` pages the layer used, and sets `Crawl-delay: 10`, which its module already honoured. Both are usable.
  - What has NOT changed: a `User-agent: *` disallow is binding (mi.tv's `/async` stays off-limits), and a robots.txt that **cannot be read at all** — connection closed or DNS failure, as with `services.tycsports.com`, `epg.orangetv.orange.es` and `movistarplus.es` — is still treated as disallow under RFC 9309, because the policy is unknown rather than permissive.
- One fetch per day per source, not polling
- No login/paywall bypass
- Personal, non-commercial use only — revisit sourcing (esp. JustWatch-style unofficial APIs, if used later) if this ever becomes shared/public

## Architecture (proposed, lightweight)
- Hosting: Vercel (consistent with existing ZP stack familiarity)
- Storage: small DB (Supabase) or flat JSON in blob storage — no need for anything heavier at this scale
- Refresh: daily scheduled job (Vercel cron) pulls fixtures + runs scrapers + runs matching, writes result set
- Frontend: simple read-only view, no auth needed for single-user personal use

## Daily refresh scheduling — why the trigger is Vercel, not GitHub (fixed 2026-08-13)

The user: "we need to find a solution to the updating times. It doesn't happen for hours after we set it up." It was not a hunch — **GitHub Actions' `schedule` trigger was late every single day, by 1h55m to 6h18m** (median ~3h30m) against a `13 6 * * *` cron. On all eight runs measured, `created_at` equals `run_started_at`, which is the decisive detail: the wait is GitHub *creating* the run, not waiting for a runner, so it is not fixable by picking a quieter minute (06:00 → 06:13 had already been tried for exactly that reason and made no difference). `workflow_dispatch` runs, by contrast, start the instant they are dispatched.

- **`api/refresh.js` + the `crons` entry in `vercel.json` are the real trigger.** A Vercel cron at `10 5 * * *` GETs `/api/refresh`, which POSTs to the workflow's `dispatches` endpoint. Vercel's own precision is per-minute on Pro and ±59 min on Hobby; **this project is on Hobby** (its Cron Jobs page states the 1-hour window), so the job fires between 05:10 and 06:09 UTC and the refresh still completes before 06:10 UTC, against 08:08–12:31 before. **Proven end to end 2026-08-13** via the Run button on that page: dispatch created *and started* at 08:20:29, fresh data committed by 08:23:27 — under three minutes, with zero queueing delay.
- Two Production env vars, set in the Vercel dashboard and never committed: **`CRON_SECRET`** (Vercel sends it automatically as `Authorization: Bearer <value>` on cron invocations; the route rejects anything else) and **`GH_DISPATCH_TOKEN`** (a fine-grained GitHub token scoped to this repo with *Actions: Read and write*).
- **`middleware.js` excludes `/api/refresh` from the site's Basic Auth gate** — the cron sends a Bearer token, not Basic credentials, so the gate would 401 it. The route's own `CRON_SECRET` check is what guards it instead.
- **GitHub's cron survives as a backstop, moved to `47 11 * * *`**, so a Vercel failure can't silently stop refreshes — the failure mode the user most dislikes. A **freshness guard** reads `fixtures.json`'s own `generatedAt` and skips the whole job when it is under 10h old, so on normal days the backstop costs ~10 seconds and **zero** fetches. That guard is what keeps this compatible with the one-fetch-per-day-per-source hygiene rule above; only `schedule` runs are gated, so a manual or Vercel-dispatched run always proceeds.
- **Do not "fix" this by adding more GitHub cron entries.** It would not improve punctuality (every trigger is queued independently) and running ~25 sources several times a day breaks the scraping-hygiene rule.

## Football "Catch up" — replays and highlights (added 2026-08-12)

Third vertical to get the catch-up treatment, at the user's request ("I know some leagues are more difficult to track, but this is a requirement"). Football's view is a **two-mode toggle — Fixtures / Catch up** — not the three-mode one MLB and Fights use, because the football sidebar's "Recently played" panel already *is* the Past view and stays available in both modes. `scripts/build-data.js` emits `replaySchedule` into `fixtures.json` in the identical row shape the other two verticals use, so the shared `renderCatchUp()` renders it unmodified.

**Sources — both legs reuse EPG layers this repo already had, now properly shared:**
- `spike/replays/tvguide.js` is a **new shared UK layer** extracted from the fights scraper: it fetches/parses/dedupes whole channel-days and memoizes per (channel, date), so the football and fight scrapers overlapping on Sky Sports Main Event and TNT Sports 1/2 costs one fetch, not two. Exactly the same split `spike/replays/tvpassport.js` already had for MLB/fights. `fight-replays.js` was refactored onto it with no behaviour change (regression test + full rebuild both verified). Note the memoization is per-process, so the 3 channels shared between `build-data.js` and `build-fights.js` are still fetched once each per script — 9 duplicate requests per daily run, deliberately accepted to keep each sport's build independently failable.
- It also exposes `nextStartUTC` per row. tvguide publishes **no duration field**, but the gap to the channel's next programme *is* the slot length — so football catch-up rows get real end times rather than the stand-in the fights rows use.
- **UK channels** (`spike/replays/football-replays.js`): Sky Sports Premier League, Sky Sports Football, Sky Sports Main Event, TNT Sports 1/2/3/4, Premier Sports 1/2. Premier Sports is the one that pays off least obviously and matters most — it re-airs the **Brasileirão**, measured at 99h and 107h after kickoff.
- **NA stations** (TV Passport): beIN Sports USA + beIN Sports en Español (the full CONMEBOL slate, genuinely re-aired — the Libertadores tie played on the 11th was listed again at 17:00 on the 12th on both), TUDN (Liga MX + condensed "en 60" replays), TyC Sports (Liga Profesional, Copa Argentina), CBS Sports Network (UEFA; already fetched for fights).
- **South American channels — added 2026-08-12 at the user's request** ("we need more sources, especially local SA ones: Argentina, Brazil and Mexico, minimum"), and they immediately became the bulk of the view: **12 rows → 97**. Two new EPG layers, because no single source covers all three markets:
  - **`spike/replays/gatotv.js` (gatotv.com) — Argentina and Mexico.** robots is `User-agent: *` / `Allow: /` with only error/terms/contact disallowed, no AI-agent blocks. Server-rendered, schema.org microdata, `<time datetime>` for **both start and end**, sports rows tagged with a `deporte` class and the competition carried as a subtitle. Channels: TyC Sports, ESPN Argentina 1/2/3; Azteca Deportes, Azteca 7, TUDN México, ESPN México 1/2, Fox Sports México. **Azteca Deportes turned out to be the strongest single SA channel** — it re-airs the Brasileirão as well as Liga MX.
  - **A GatoTV channel page can exist, return HTTP 200 and still carry no schedule whatsoever** — this is the trap on that host and it cost real coverage. `/canal/fox_sports_argentina`, `/canal/fox_sports_premium_argentina` and `/canal/tnt_sports` all render a page whose only `tbl_EPG_row` elements belong to the **"Disponibilidad" (provider availability) table**, with zero `<time>` elements and zero programme titles. Counting `tbl_EPG_row` therefore *lies*; the real test is `.div_program_title_on_channel` plus `time[datetime]`. Two further sweep lessons: matchups live in the **title on some channels and the subtitle on others**, so a title-only probe under-reports badly (Fox Sports Cono Sur looked empty and actually had 9), and several feeds are **byte-identical duplicates** — `espn_sur == espn_argentina`, `espn_2_sur == espn_2_argentina`, `espn_internacional == espn_norte` — so listing both would double every row. Fox Sports Argentina's real listings live under **`fox_sports_cono_sur`**.
  - **`spike/replays/fulltv.js` (fulltv.com.ar) — Argentina, and only because nothing else reaches TNT Sports Argentina** (the Liga Profesional's main channel), which GatoTV has no data for at all. robots allows the `/tv-vivo-deportes/canal-*.htm` pages, disallows a set of `.php` endpoints including `/programacion.php`, and sets **`Crawl-delay: 10`, which the module honours**. **Today only**: the day tabs call `programacion_lista()`, which (checked in `/js/canal.js`) merely toggles CSS classes — the other days are not in the page and no permitted endpoint serves them. Titles append fixture context after the matchup ("Independiente vs. Platense, Fecha 4 - Grupo A, Estadio Libertadores de América - Liga Profesional 2026"), so the matchup is the part before the first comma. Also checked and rejected for this gap: **americatvguide.com** — permissive robots and real listings, but its TNT Sports entries are titled only "Liga Profesional 2026" with no teams, so nothing can be correlated; and **tntsports.com.ar** itself, which 403s even robots.txt.
  - **`spike/replays/guiadetv.js` (guiadetv.com) — Brazil**, which GatoTV does not cover at all (it's a Spanish-language guide; `/canal/sportv` and `/canal/premiere_clubes` both serve a soft-404 "Pagina No Encontrada" body under HTTP 200 — the trap to watch for on that host). robots is `User-agent: *` / `Disallow:`, fully permissive. Every entry carries `data-dt="YYYY-MM-DD HH:MM:SS-03:00"` — **an explicit UTC offset, so no timezone inference at all**, making this the most trustworthy of the four sources. And **one fetch returns eight days** (the day tabs are `scrollToDiv()` anchors inside the same page, not separate URLs), so a channel costs exactly one request. Channels: Premiere, SporTV 1/2/3, ESPN Brasil. Premiere alone listed 232 matchups on the check day.
- **Latin American listing conventions**, all handled and regression-tested: the Brazilian matchup separator is **" x "** not " v "; **"VT - "** prefixes a videotaped (replay) airing and **"AO VIVO"** a live one — a native replay/live flag neither other EPG offers; and GatoTV runs **two opposite layouts** — TyC and Azteca put the matchup in the *title* with the competition beneath, while TUDN inverts it ("Fútbol Mexicano Primera División" / "Toluca vs. Necaxa") — so both fields are parsed.
- **Brazil guide furniture is stripped before correlation**: future cards arrive as `Hoje a partir das HH:MM - ...` or `Dia DD/MM - ...`, and live/pre-match cards can carry `AO VIVO` or `Pré-Hora:`. `cleanBrazilListingTitle()` removes those prefixes, which is why Premiere 2/3/4 rows now reach the same fixture keys as SporTV instead of silently falling out. The three fixture scrapers also seed Brazil/Argentina/Mexico market groups, while legacy flat channels remain visible as residual "Other listed" rows.
- **Brazil has two supplements in `fixtures.json`**: `brazilReplaySchedule` includes the strict tracked-match replays plus Guia de TV's explicit `VT -` programmes even when their match is outside the fixture feed, while `brazilGuideSchedule` includes the complete current/upcoming live, scheduled and replay grid from every Brazilian Guia de TV channel. The UI exposes All replays, Brazil replays, and Brazil guide; direct VT rows have no fabricated watch key or team logos and are labelled as Guia de TV listings.
- **Argentina now has the same explicit coverage paths**: `argentinaReplaySchedule` is the strict tracked-match replay feed, while `argentinaGuideSchedule` is the complete current/upcoming matchup grid from DirecTV Argentina plus TyC's live agenda. The UI exposes Argentina replays and Argentina guide alongside the Brazil views. DirecTV does not publish a native replay flag, so only rows pinned by the normal post-kickoff correlation are called replays; unmatched rows stay honestly labelled as Argentina guide listings.
- **The cross-market channel view is now explicit**: Mexican ESPN feeds are labelled `Mexico` rather than disappearing into generic US/Canada Spanish, `spainReplaySchedule`/`spainGuideSchedule` expose Spain's live and catch-up channels directly, and `allGuideSchedule` combines every current/upcoming market (UK, US, Canada, Argentina, Brazil, Mexico, Spain, Portugal, Italy, Germany and France). The Football catch-up controls expose All channels plus the country views, while All replays remains the complete catch-up list.
- **GatoTV times are the CHANNEL'S OWN COUNTRY local time**, not the visitor's (it's a per-country guide with no timezone selector). Verified rather than assumed: our own fixture data has Atlético Tucumán v Independiente kicking off 19:15 ART, TV Passport shows TyC carrying it live at 19:00 ART, and GatoTV lists it at 23:00 ART — i.e. a re-air 3.75h later, which only makes sense under the country-local reading. Talleres v Lanús corroborates it at 3.9h. The zone is declared per channel by the caller and never guessed.
- **Ruled out with evidence, live-checked 2026-08-12 — don't re-try on a hunch**: GolTV USA (tags a league but *never* any teams — every listing is "Primeira Liga Soccer —" with an empty episode title; also carries no tracked competition), ESPN Deportes (no soccer matches at all, just *Fútbol picante*/*Equipo F* talk plus MLB), Fox Soccer Plus (real structured soccer, but Canadian Premier League / CONCACAF U-20 / Saudi league / rugby), FS1 and FS2 (Leagues Cup only), Telemundo and NBC Universo (zero soccer listings in the sweep). For Latin America specifically: **mi.tv** (covers ar/br/mx from one template and its robots is permissive, but it renders **zero** listings server-side — they load from the `/*async*` endpoint its own robots.txt disallows, so it is off-limits, not merely awkward), **Globo's own sportv/premiere programming pages** (JS-driven, zero server-rendered time tokens; Globo also blocks CCBot/GPTBot/Google-Extended though not Claude), **DirecTV Latin America** (403), and programacaodatv.com.br / meuguiadetv.com (both unreachable).

**Two structural gotchas, both validated and handled:**
1. **TV Passport's `data-team1`/`data-team2` are REVERSED relative to its own episode title** on beIN ("… — Fluminense vs. Independiente Rivadavia" with `team1=Independiente Rivadavia`). Side order therefore carries no information and matchups are compared as an **unordered pair** — which is what the correlation does anyway.
2. **Structured team attributes exist only on full-match listings.** Condensed shows ("Liga MX en 60", "90 in 30") carry the matchup only in `episodeTitle`, so both paths are needed.

**Correlation** (`correlateFootballAirings` in `scripts/build-data.js`, exported pure, covered by `spike/test-football-correlation.js` / `npm run test-football` — 20 cases built from real captured listing strings): an airing pins to a match when both team names resolve — through the existing `normalizeTeam`/alias table — to that match's keys as an unordered pair, AND it airs **2h–7d after kickoff**. The 2h floor excludes the live broadcast (a football listing starts at or just before kickoff and runs ~2h); the 7d ceiling is exactly how long a match stays in `recentEvents`, and it has to be that wide because of Premier Sports' 99h Brasileirão re-airs — far beyond MLB's 72h window. Where two meetings of the same teams qualify, the most recent wins. Correlated against **upcoming *and* recent** matches: a match played earlier today is still in `events` until the next build reclassifies it, and tonight's game re-aired at midnight is exactly a catch-up row.

**The archive guard is the load-bearing part, and is football-specific.** These channels fill their off-hours with old matches on a scale MLB and fight networks don't — Sky Sports Premier League was ~80% archive on the check day ("PL Greatest Games", "Premier League Years", "Championship Retro", "EFL Greatest Games"). Without a guard, a "Rangers v Celtic from the 2020/21 season" re-air would attach itself to a Rangers v Celtic played last week. `ARCHIVE_RE` is built from real captured strings (`2021/22`, `from 2010`, `in the 2013 …`, `in the 2025/26 final`, Greatest Games / Retro / Classic / Season Review / Legends / 100 Club / Cult Heroes / Rivalries) and archive-flagged airings never attribute. **tvguide.co.uk carries no repeat flag and no original-air date** — confirmed by dumping raw row markup, which has only `data-date`, a programme link, title and two descriptions — so this text guard plus the time window is all there is; there is no flag to trust.

**Only attributed rows are listed for the general football replay feed** — deliberately unlike MLB and Fights, which also emit matchup-only rows for airings they can't pin down. Brazil is the documented exception because Guia de TV supplies a native `VT -` replay marker: those rows are safe to list without guessing a parent fixture and are counted separately as `supplemented` in diagnostics. Other Brazilian guide rows remain in `brazilGuideSchedule` rather than being mislabeled as catch-up.

**Honest labelling**: rows say **"Full replay"** or **"Highlights"**. `HIGHLIGHTS_RE` catches the English, Spanish and Portuguese forms ("Highlights", "Hlts", "en 60", "90 in 30", "Goals", "Melhores Momentos", "Resumo/Resumen", "Gols", "Compacto"), and on top of that **any slot shorter than 75 minutes is treated as condensed whatever the listing calls itself** — Premiere schedules its "VT" Brasileirão re-airs in 30-minute slots, and a football match cannot be re-aired in full in half an hour. On these channels a condensed show is often the only re-air a match gets, and calling that a replay would overpromise — but dropping highlights would gut the view, since that is how football catch-up actually works.

**Argentina — `spike/replays/directv-ar.js` — the Radware captcha is INTERMITTENT, not permanent. Do not retire this module (corrected 2026-08-16).**

For about 21 hours — incident opened `2026-08-15T22:13Z`, closed `2026-08-16T19:11Z` — `directv.com.ar` served **Radware Bot Manager (ShieldSquare) captcha interstitials on every path**: `/`, `/guia/guia.aspx` and `/guia/ChannelDetail.aspx` all answered **HTTP 200 with a captcha page**, which is why the health panel showed 13/13 channels failing with `Unexpected token '<', "<!DOCTYPE "... is not valid JSON` — the module was parsing a captcha page as JSON. Only `/robots.txt` stayed normal throughout, and it still permits the endpoint, so this was never a policy change.

**It then recovered on its own, with no code change: 13/13 channels healthy again.** An earlier version of this doc called the source "finished, not coming back" — that was wrong, and stated far too confidently on a single day's evidence. The correct reading is that this host puts a bot wall up under some conditions and takes it down again.

- **What has NOT changed: never try to work around it.** Solving or evading a CAPTCHA is off-limits regardless of what robots.txt allows. When the wall is up the layer simply fails, the health panel says so, and the incident log records it — which is exactly the designed behaviour.
- **The failure is self-healing, so the right response to it is to wait**, not to rewrite the module. The incident log (`health.json`) is what distinguishes a wall that lifted from one that stayed up; check `resolvedAt` before concluding anything.
- If it ever *does* stay down for good, the documented replacement is **`fulltv.com.ar`** — verified reachable and captcha-free on 2026-08-16 (robots 200, guide page 200 with real listings) and already permitted under the corrected robots rule. It only reaches TNT Sports Argentina and only for today, so it is a partial replacement, not a like-for-like one.

- **Timezone verified against an independent source, not assumed** — the page publishes bare wall-clock with no offset, the exact shape that got GatoTV removed. The anchor: SuperGuidaTV (itself verified, Europe/Rome) lists the Tour of Czech Republic's **4th stage** at 11:00Z, and tvinfo lists the **4th stage** at 13:00 — UTC+2. **The stage number is what makes it decisive**: a UTC+1 reading would instead pair tvinfo's 3rd stage against the Italian guide's 4th, which is a different race. It also excludes visitor-local rendering, since the build ran from UTC+1. Corroborated by the European Athletics marathon at 06:25Z against tvinfo's 08:25.
- **The columns roll past midnight and handling it is load-bearing.** A German broadcast day runs ~05:00 to ~03:00, so a column headed 16.08 ends `23:00, 00:00, 02:00, 03:00` — and those last three belong to the 17th. Times within a column ascend, so a decrease *is* the rollover. The same trap that put SuperGuidaTV's ties on the wrong date.
- **Channels kept** (swept all 159): **DAZN Deutschland** (the big one — Bundesliga Fri/Sun, and already carrying Serie A, Ligue 1, La Liga and Coppa Italia between seasons), **Sky Fussball Bundesliga**, **Sport1**, **Sky Sport Austria** (not a duplicate — it alone had the UEFA Supercup and the Austrian Bundesliga; Austria shares Germany's clock), **Sportdigital1+**. **Rejected as checked-and-empty: Eurosport and Eurosport 2** (48 and 65 programmes over four days, *zero* football — cycling, snooker, athletics) and **DF1** (general entertainment; its only football in four days was the women's Supercup final). **Sky Sport Bundesliga 1-10 and Sky Sport Top Event are absent from tvinfo's index entirely** — that is a real gap with no permitted alternative, since every other German guide is blocked above.
- **Listing conventions**, all regression-tested in `spike/test-football-correlation.js` against real captured strings: the competition sits in the **title** ("Fußball: 2. Bundesliga") and the matchup in the **subtitle** ("Holstein Kiel - FC St. Pauli, 2. Spieltag"), so both fields are parsed — the same two-opposite-layouts problem GatoTV had. `parseGermanMatchup` takes the text after the **last colon** (stripping "Highlights XXL:", "90in30:", "Finale:" lead-ins), cuts at the **first comma** (round and venue context), drops a trailing country tag ("Aston Villa/ ENG"), and rewrites the first spaced hyphen to a separator the shared parser knows. Unspaced hyphens survive, so "Rot-Weiss Essen" is safe — the same reasoning as SPORT TV's "AL-DIRIYAH".
- **The season guard needed its own form.** German listings tag the season **bare** ("Serie A 26/27", "Coppa Italia 26/27") where the Spanish guides parenthesise it, and `ARCHIVE_RE` sees neither. `isStaleGermanSeason` normalises the bare form into the parenthesised one and reuses `isStaleSeason`, so the rollover logic is not duplicated and the other eight layers are untouched.
- **German EXONYMS are the real integration risk and are why this needed alias work.** German listings write "Inter Mailand", "SSC Neapel", "OGC Nizza" and "Racing Straßburg" — spellings **no other source in this project uses** — so without aliases every Serie A and Ligue 1 re-air on DAZN Deutschland would have silently failed to attribute. Eleven aliases added, each spelling read off a real tvinfo listing (its "Serie A 26/27" / "Ligue 1 26/27" pages, reachable now precisely because the horizon is 4 weeks) and each target verified against a key that actually exists in the fixture set.
- **The trap on this source: "PSG" is deliberately NOT aliased.** The fixture feed's `paris` key is **Paris FC**, a different club that tvinfo also lists ("Paris FC - OGC Nizza"). Mapping PSG onto it would attach Paris Saint-Germain's matches to Paris FC's fixtures. Clubs with no fixture in the window — Barcelona, Juventus, Lazio, Roma, Milan, Bologna, Atalanta, Lecce, Fiorentina and every Bundesliga side — are left alone for the same reason the La Liga block was: the canonical key must be read off the feed, not inferred from the German name.
- **Expect it to look empty until late August, and that is correct.** First build: **5/5 channels healthy, 260 programmes read, 94 matchups parsed, 0 catch-up rows and 1 live market group** (DAZN Deutschland on Mirassol v Flamengo). Every parsed matchup was 2. Bundesliga, the Austrian Bundesliga or Coppa Italia — none tracked — because Ligue 1 opens 21 Aug, Serie A 22 Aug and the Bundesliga 28 Aug. The end-to-end chain was proven by correlating a real captured listing ("Inter Mailand - SSC Neapel") against a Serie A fixture rather than waiting for the season: it produces a row. **Do not judge this layer before ~31 Aug** — use the catch-up accounting panel, which distinguishes "fetched nothing" from "fetched plenty and matched none".
- `magenta.tv` remains fully permissive (`User-agent: *` / `Allow: /`) and unused — its EPG is a session/manifest API needing real reverse-engineering. It is the fallback if tvinfo ever breaks, and the only remaining route to the Sky Sport Bundesliga feeds.

## The schedule redesign (2026-08-16) — why the layout changed shape

The user: *"As it grows the current design doesn't work… it's beginning to look messy. Use best practices to organize all the information in a natural way. Also instead of Europe add the different countries."*

The old layout nested **date → country → competition → a poster card per match**, and each card listed every channel in every market inline. Measured before the change: **123 cards, median 257px tall, 486 channel chips on screen, 34 screens of scroll** on the football tab alone. The decisive flaw was that card height scaled with *matches × markets* — so **every source added made the dashboard worse**, which is exactly backwards for a project whose whole activity is adding sources. Germany was the ninth market and the one that made it obvious.

**Date → time slot → fixture row**, and country/competition demoted from nesting levels to facets.
- **Time is the ruling axis** because that is the question the page answers, and it is how every broadcast listing in the world is organised. Nesting on a facet fragmented each day into "Saturday → Spain → La Liga → 1 match" stubs; that fragmentation *was* the mess. Country is now a filter pill and a row tag, which scales to any number of countries.
- **Kick-off is printed once per slot, not once per row.** Denser, and more truthful: six Bundesliga matches at 15:30 genuinely are one moment on one app (see the DAZN note above), and stacking them under one time is the fact a viewer needs.
- Result: rows are **40px** against 257px, and the page is **7.4 screens against 34** — with strictly more information reachable.

**The carriage strip is the load-bearing device.** Each row carries a compact run of market codes (`ESP ARG ITA UK US`) plus a channel count, and the channels themselves live behind the row's own disclosure. **A tenth market widens a strip; it does not lengthen the page.** This is the property the old layout lacked and the reason the redesign should survive the next five sources.

**Two encodings, deliberately separated**: a **three-letter code** carries country identity (ENG/ESP/BRA — the football world's own vernacular, so no legend is needed, and unlike flag emoji it renders identically on Windows), while **colour carries region only** (South America / North America / Europe). Ten country hues would be mutually indistinguishable — three of them would be blues. Don't "improve" this by colouring each country.

**Days are grouped by UK date, not venue-local date.** The rail is in UK time, and the two must agree: a Liga MX match kicking off 19:10 in Monterrey is 02:10 UK, and filing it under the Mexican Saturday while the rail reads 02:10 puts a match on a day it cannot be watched on. Venue-local kick-off is still shown, in the row's detail, as context rather than as the organising axis. (This does **not** contradict the MLB catch-up convention above, which labels *replay rows* by the game's venue-local date — a different view, different job.)

**"Europe" is gone from the country axis**, per the request: `EURO_COMPETITION_COUNTRY` in `build-data.js` gives each league its own country (England, Spain, Germany, Italy, France), leaving "Europe" only for the Champions League, which genuinely has no home country. **A real consequence beyond the filter bar**: the home market now falls out of the country directly, so `COUNTRY_HOME_MARKET` replaced the per-competition table — and **Serie A finally leads with Italian channels**, a gap that existed only because every European fixture used to say "Europe".

**European clubs gained display names.** football-data.org registers clubs under full legal names ("Real Racing Club de Santander", "FC Internazionale Milano") that no broadcaster or table uses and that crowded the team name out of a row — 45 of 156 names were truncating. Adding the everyday names to `team-display-names.js` cut that to 11, all of them Argentine names this doc deliberately expanded for disambiguation. Display names are cosmetic and keyed off the same normalized key the alias table resolves to, so **matching is untouched**.

**Fights deliberately kept their cards.** A handful of events a week, each with real poster artwork, an org mark and a full undercard, is genuinely a card problem. The schedule row exists to compress a hundred near-identical fixtures; there is nothing to compress here, and a row would throw away the artwork. `renderFightCards` is separate from `renderEventsGrouped` for this reason — MLB shares the schedule, fights do not.

**Two traps worth not re-learning:**
- **The health panel no longer auto-expands on a down source.** That rule was right when nothing was ever down and wrong the moment something stayed down: the panel is ~1400px of per-channel accounting, so with DirecTV permanently captcha-walled it buried the entire dashboard below the fold on *every load* — the first match sat at 1753px. The red chip in the header already makes a failure impossible to miss and costs no vertical space, so the chip now shouts (solid red, not outlined) and the panel stays one click away, capped at 60vh with its own scroll.
- **The country filter wraps, it never scrolls sideways.** It shipped as a horizontally scrolling strip with `scrollbar-width: none`, which meant that under ~1080px four of the nine countries sat off the end of the bar with no scrollbar, no fade and no arrow to say so — the user's "how am I supposed to scroll through the countries?" was a genuine dead end, not a preference. There are nine of these, not ninety; they fit on two rows.
- **The accumulate-history step must re-derive the country, not just the team keys.** It already re-runs stored keys through the alias table so an archived entry picks up a later fix; the country needed the same treatment and it was not hypothetical. When the European leagues stopped sharing one "Europe" bucket, every La Liga fixture already in the archive kept saying Europe while fresh ones said Spain — the same competition filed under two countries on one page, which is what the user spotted. Only competitions with a fixed home country are refreshed: a continental cup's country is resolved from the clubs involved and must not be overwritten by a static lookup.
- **The narrow-row rules are a `@container` query, not a media query**, because the same row renders in the main column, in the 340px "Recently played" sidebar and on a phone. Keyed to the viewport it collapsed the sidebar's teams column to **zero width** while the viewport was still "desktop". And it **must sit after the base row rules** — a container query adds no specificity, so placed earlier it silently loses to them, which is exactly how it failed the first time.

## Search (football only, built 2026-08-26)

The user: *"a search bar that shows what I search. If I begin typing Boca, it should automatically show the scheduled live games for Boca (with all the information about broadcast, etc.), and all the scheduled replays."*

**Search cuts ACROSS the Fixtures / Catch up toggle rather than filtering inside whichever one is open**, and that is the whole design decision. "Boca" asks two questions at once — *when do they next play and who shows it*, and *where can I still watch the last one* — and those answers live in different data sets. An active query therefore hides the mode's view, both of its filter bars and the country pills, and renders a combined results view in `#soccerSearchResults`; clearing it calls `renderSoccerMode(soccerMode)` and restores the mode exactly as it was (verified from both Fixtures and Catch up). The country pills are hidden deliberately — a facet filtering only part of a multi-section result set would be a trap.

- **Four sections, each reusing an existing renderer, so nothing about broadcast display is re-implemented**: *Scheduled matches* and *Recently played* via `renderEventsGrouped` (so the row disclosure, the full per-market channel list, the leg-1 context and the watched checkbox all work unchanged), *Catch up* and *Channel listings* via `renderCatchUp`. A section is only rendered when it has rows; nothing matching anywhere gives one honest empty line.
- **Every replay feed is searched, not just `replaySchedule`** — the country feeds carry rows the strict tracked-match feed deliberately leaves out (Brazil's native `VT -` markers), and a search for a team should find its replay wherever it was listed. Deduped on channel + air time + label, since the same airing legitimately appears in more than one feed. `allGuideSchedule` is searched separately as *Channel listings* and de-duped against what the replay sections already showed.
- **The haystack includes the normalized `watchKey` as well as the display label, and that is load-bearing.** The sources spell teams differently — a guide writes "U. Catolica" where the key correlated to it reads `universidad catolica` — so a query hits whichever form it happens to match rather than depending on which source wrote the row. Matching runs through the existing `simplifyName` (lowercase, accents stripped), so "atletico" finds "Atlético", and **every** token must appear, so "boca river" narrows to the derby while "boca" alone keeps everything Boca.
- **Competition and channel names are in the haystack too**, which is the multi-market point from the Audience section: "Libertadores" or "Premiere" is as natural a question as a club name. Measured on the build day: "Premiere" returns 171 catch-up airings across 5 fixtures.
- **The *Channel listings* section carries the guide feed as-is, so it is only as football-only as the gates upstream of it.** Searching Boca is what exposed the leak: DSports+ carried "Sesi/Franca vs. Boca Juniors" — a Basketball Champions League Americas tie, since Boca's basketball side shares the football club's name. Fixed at source (see below); the section still says "not pinned to a tracked fixture", because an uncorrelated row genuinely is a guide listing rather than catch-up.
- Two chars minimum (one character is noise, not a query); below that the normal view returns. Escape and the × button clear it. Haystacks are cached in a `WeakMap` since each keystroke re-scans ~3000 catch-up rows. A query typed while the initial fetch is still in flight is re-run when `load()` resolves — the box is usable before the data arrives.
- **Football only for now, by request.** MLB and Fights are untouched. The matching helpers are sport-neutral, but the section list and every feed name in `soccerReplayRows()` are football's.

**Non-football rows in the guide feeds — diagnosed and fixed 2026-08-26**, after the user spotted "Sesi/Franca v Boca Juniors" on DSports+. Measured before fixing: **4 leaked rows out of 1,759** in `allGuideSchedule`, from two different causes.

- **The volleyball rows named their sport and nothing caught them**, because `NOT_FOOTBALL_RE` only knew English/US-league terms (NFL, MLB, NBA, UFC). Sky Sport Arena's "Italia - Germania Volley..." is now caught by adding basketball and volleyball in English, Spanish, Portuguese and Italian to that shared gate. Safe to put there — none of those words can appear in a football listing, and it kills them at source across every market.
- **The basketball row named NOTHING.** DirecTV's payload is `title: "Sesi/Franca vs. Boca Juniors"`, `description: ""`, `category: "Series"` — no competition, no sport, no flag. **No text rule could ever have caught it**, which is the point worth remembering: these layers deliberately have no positive football gate (an Argentine listing is very often just two club names), so a two-club row from any sport parses as a football matchup. It took adding the club itself to `ARGENTINA_NON_FOOTBALL_RE`, whose existing MLB-club list exists for exactly this reason. Matched as the whole `sesi/franca` token and **never bare `franca`** — *França* is Portuguese for France and would swallow the national team's fixtures.
- **The guard now follows the ROW's market, not the view's.** It read `market === "Argentina"`, which is the requested view, so anything it caught was filtered out of the Argentina guide and **still appeared in All channels** — which is precisely where the basketball row was showing. Now `airing.market === "Argentina"`.
- **Known and deliberately left alone: `Irish Wolves v Dublin Guardians` on TNT Sports 4.** The Argentine guard would match it (on "Guardians", from the MLB club list) but never runs on a UK row, and widening a US-baseball club list to the UK market is how you start deleting real football. It is a separate pre-existing leak on the UK path, not this one.
- Verified against **all 4,254 rows in the shipped data**: exactly the intended rows are filtered, zero false positives, and "França"/"Franca EC" survive. Re-checked live against the real DSports+ and Sky Sport Arena listings — 1 of 38 and 1 of 22 programmes dropped, both the right ones.

**The Brazil VT supplement needed a scope bound too — same day, different mechanism.** The user, immediately after the basketball row: *"there are matches from the portuguese league, like Porto v União Torrense"*. That row came in through the documented Brazil exception (any Guia de TV listing prefixed `VT -` becomes a catch-up row even with no parent fixture), not through any guide view — and unlike the basketball case it was in `replaySchedule` itself, the main catch-up feed.

- **The supplement was 343 of the 626 rows in that feed — 55%**, and auditing it showed Portugal was one leak of several: the Eredivisie (PSV, Ajax, Utrecht, AZ), the Saudi and Turkish leagues, **a volleyball tie (Osasco x Pinheiros, 7 airings) and two boxing cards**. The raw title is again just `VT - Porto x União Torrense` with an empty description, so — exactly like Sesi/Franca — no text rule could tell it apart.
- **The bound is now: a VT row must name at least one club from the tracked fixture set** (`events` + `recentEvents`, the same universe the correlation itself runs against). Chosen over a Portugal-specific blocklist because it needs no league list to maintain and it follows whatever this dashboard tracks, and over dropping the supplement because that supplement is where the Brasileirão VT re-airs live. Result: **287 rows kept, 56 dropped.**
- **Known consequence, accepted deliberately: Brazilian Série B re-airs go with them** (Operário-PR x Vila Nova, Ponte Preta x Avaí, Atlético-GO x Botafogo-SP). Série B fixtures are not tracked either, so those rows had no parent to return to. If Série B is ever wanted, add the competition rather than loosening this gate.

This is the same class of bug the German exonyms needed, and it rescued 10 rows that the new gate would otherwise have dropped.
- **The five aliases deliberately NOT added, each a real collision**: `vitoria guimaraes` → `vitoria` (Vitória SC of Guimarães vs EC Vitória of Salvador — the exact collision that keeps Liga Portugal out of the SPORT TV layer), `braga` → `red bull bragantino` (substring coincidence), `america mg` → `america` (the feed's América is Club América of Mexico City), `botafogo ribeirao preto` → `botafogo` (two different clubs, which is why the -SP suffix exists), `charlton athletic` → `athletic` (Athletic Club is Bilbao). **The guide feeds got the same bound, an hour later.** The VT gate cleaned `replaySchedule` completely (0 out-of-scope rows of 236) but the guide views kept theirs, since they had no gate at all — 41 rows in `allGuideSchedule`, 26 in `brazilGuideSchedule`. Sociedad", "Fulham v Chelsea Premier League" and "Valencia CF v RC Celta", because only one side of each resolved. ## Source health — knowing when a scraper breaks (built 2026-08-12)

Built at the user's request ("notifies us of which scrapers have failed, so I can contact you and get it fixed"). With ~25 sources across four build scripts, a scraper breaking was previously invisible in the app — the page just quietly showed less, and the only trace was a line in a build log nobody reads.

- **`spike/source-health.js`** is the shared collector. Every source calls `recordSource(id, {label, group, ok, error, items, channelsOk, channelsTotal})`; `writeHealth()` merges into `public/data/health.json` at the end of each build. **Merged, not overwritten** — the four build scripts are separate processes and each records only its own sources, so a wholesale write would erase the others'. `lastOkAt` is carried across runs, which is what turns "failing" into the far more useful "failing since 3 days ago".
- **Three states, and the middle one matters**: `ok`, `degraded` (the source worked but some of its channels errored — e.g. 16/19 on GatoTV), and `down` (produced nothing). Treating a couple of dead channels as a hard failure would train the eye to ignore the indicator, which defeats the point.
- **UI**: a chip in the site header, on every sport tab — green "All 20 sources OK", amber "N degraded", red "N sources down". Click to expand a per-source list grouped by area, showing channel counts, item counts, when it was last checked and — for anything broken — the actual error text and how long it's been failing. **A `down` source auto-expands the panel** so it can't be missed; degraded and ok stay collapsed.
- **Isolating failures was part of this, not a separate cleanup.** `collectRaw()` in `build-data.js` previously called the Brazil/Argentina/Mexico scrapers unwrapped, so a transient `[mexico] HTTP 520` (seen live on 2026-08-12) aborted the whole run *before* fixtures.json was written — which would also mean never publishing the health status explaining why. All four fixture sources are now individually wrapped, matching this doc's stated failure policy. A country returning nothing for one run doesn't lose its matches: the accumulate-history step merges the previous run's events back in, so the page degrades to slightly stale rather than empty. `build-standings.js` got the same treatment for its two scrapers.
- `health.json` is in the workflow's commit list alongside the other data files.

## Catch-up accounting — why a fetched airing never became a row (built 2026-08-13)

Built after the user asked what could be better. The build logged "1151 fetched, 194 attributed", which says a loss happened and nothing about where — and that gap had already cost real time: **Liga MX showed zero rows for days while TUDN was demonstrably re-airing Liga MX matches**, and finding out why (the round hadn't been played inside the 7-day window because the clubs were in the Leagues Cup) took a bespoke investigation. The deeper problem is that source health reports whether a scraper is **reachable**, not whether it still **works**: a channel whose listing format quietly changes looks exactly like a channel having a quiet week.

- **`spike/replay-diagnostics.js`** tallies every airing per channel at the point it is discarded: `fetched`, `parsed`, `attributed`, and drops bucketed as `notFootball`, `unparsed`, `live`, `archive`, `untracked`, `window`, `duplicate`. Written to `health.json` as a top-level `channels[]` (merge-safe — only `build-data` sets it, so `writeHealth` carries the previous file's copy forward, same discipline `sources[]` needs).
- **`correlateFootballAirings` takes an optional `onDrop` sink** rather than reaching for the module directly, so it stays the pure, unit-tested function the regression suite calls with two arguments.
- **UI**: each catch-up source in the health panel gains a line — "569 programmes read · 206 named two teams · **74 listed**", the drop breakdown in plain words ("322 other sport · 115 not a tracked match"), and an amber "nothing listed from: …" naming channels that fetched programmes and produced nothing. That last line is the actionable one.
- **The instrumentation caught a flaw in itself first, which is worth knowing.** The Latin and Iberian layers deliberately have no positive `FOOTBALL_RE` gate (a Brazilian listing is often bare "Palmeiras x Santos" with no competition word), so every telenovela was landing in `unparsed` — Globo read as "100% unparsed" when it is a general-entertainment channel. `noteUnparsed()` now classifies a parse failure as `unparsed` only if the text actually looks like football, and `notFootball` otherwise. **Accounting only — never a behaviour gate**, since adding that gate for real would drop genuine bare-matchup listings. Total `unparsed` fell from a misleading 2621 to 366.
- **Calibration, so nobody chases a phantom**: `notFootball` and `untracked` dominating is healthy. **`unparsed` is not automatically a bug** — Sky Sports Premier League showed 51 on the first run and every one was studio or archive programming that genuinely names no teams ("Premier League Review", "100 Club", "Sky Sports FC", "Good Morning Transfers"). The signal is a **change** on a channel that was producing rows, not the absolute level.
- First real run: **4733 fetched, 1150 with a matchup, 194 listed**; drops 3217 notFootball, 609 untracked, 366 unparsed, 142 window, 111 archive, 94 live; 48 channels fetched something and listed nothing.

**The Updates tab (built 2026-08-12)** — a fourth top-level tab (`🛠 Updates`), at the user's request: "an updates section for everything, separate from the sports, with tabs for each sport, and a section with every single scraping error". It's top-level rather than a sidebar panel because the two questions it answers — *what changed?* and *is anything broken?* — are asked about the dashboard, not about a sport.
- **Per-sport update history.** Football has had a changelog since early on; MLB and Fights had none, so a channel appearing or a card being cancelled was invisible. `spike/updates.js` generalises the diff — one `diffRuns()` serves all three, because their event objects already share a shape (`homeTeam`/`awayTeam`/`localDate`/`channels`) whether the "teams" are clubs, ballclubs or two fighters. Output is `public/data/updates.json` (`{generatedAt, sports:{football,mlb,fights}}`), each build script appending only its own sport — same merge discipline as source-health, since the four scripts are separate processes. `changelog.json` is deliberately left alone so the existing football sidebar panel keeps working.
- Keys must be stable across builds: MLB uses `away|home|localDate`; **Fights uses `org|fighter|fighter|localDate` rather than the event name**, because a card's name gets rewritten between builds (a Sherdog product name giving way to the EPG's) while that trio stays put.
- **Every scraping error, including ones already fixed.** `health.json` gained an `incidents[]` log. The `sources[]` list answers "is anything broken *now*"; incidents answer "what has broken, when, and is it still broken" — which is what you need to report a source that failed overnight and self-healed. **One incident spans a whole outage**: it opens when a source starts failing, extends (`lastSeenAt`) while the same failure continues rather than appending an identical row every build, and closes (`resolvedAt`) when the source next succeeds. Capped at 60.
- Verified by fault injection through the full lifecycle, not just the happy path: forcing `[mexico] HTTP 520` opened one incident; a second failing build extended it rather than duplicating; reverting closed it with a `resolvedAt` while keeping the record visible. The synthetic incident was then pruned from the committed file — the shipped log starts empty because nothing has genuinely failed yet.

**Adding a channel**: never trust a slug resolving. Sweep it for real programme rows first (`.div_program_title_on_channel` + `time[datetime]` on GatoTV, `data-dt` on Guia de TV), check the matchup isn't only in the subtitle, and check it isn't a duplicate feed of one already listed.

## Watched tracker (built 2026-08-20)

A checkbox on every game/card and every catch-up row, so a match watched live or from any one re-air shows as already-seen on every other re-air of that same game. The user: "keep track of what I've watched already… synced across devices, not sure how it could be any other way" — ruled out localStorage outright (single browser/device only) in favour of a small server-synced store, the first piece of *write* state this dashboard has ever had (everything before this was read-only, rebuilt daily and committed to git).

- **Storage: one JSON blob** (`watched.json` via `@vercel/blob`, `put`/`get`, `access: "private"`, `allowOverwrite: true`) mapping `watchKey -> ISO timestamp watched`, in `api/watched.js` (GET returns the map, POST `{key, watched}` toggles one entry). Matches this project's stated "flat JSON, no heavier than necessary" storage philosophy (see Architecture above) rather than standing up a database for a few dozen small records. Needs `BLOB_READ_WRITE_TOKEN`, which Vercel sets automatically once a Blob store is connected to the project (Storage tab in the dashboard) — a one-time manual step, nothing to commit.
  - **Two rounds of a genuinely silent client-side revert before this actually worked, and both round-trips were guesses that should have been confirmed against a real error first.** The client's optimistic-then-revert-on-failure UX (see below) hid the server error completely, so "the box unticks after 1-2 seconds" was the entire signal for a while. Round 1 read the blob back with a bare unauthenticated `fetch(blob.url)`, which only works on a Public store — swapped to `get()`/`put()` with `access: "private"` on the theory the store was Private, still without confirming it. That was wrong the other way: the store IS Public (as originally set up), and the SDK rejects `access: "private"` outright on a Public store rather than working around the mismatch ("Cannot use private access on a public store"). The fix was reverting to `access: "public"` — the real problem was never public-vs-private guesswork, it was that nothing surfaced the actual error to check the guess against. Wrapping the handler in try/catch (puts the real message in the response body) plus reading that body client-side in `setWatched()`'s catch block (rather than just logging the HTTP status) is what actually broke the loop — the very next attempt showed the exact SDK error in the console instead of another blind guess.
- **No separate auth**: unlike `/api/refresh`, this route is NOT excluded from `middleware.js`'s Basic Auth gate, so it's already behind the site's existing login.
- **One key, shared by a game and every one of its replay rows.** Each build script computes a `watchKey` once and threads it onto both the fixture/game/card object and every `replaySchedule` row correlated to it — reusing the SAME canonical identity each sport already had for a different purpose, rather than inventing a new ID scheme: football's `eventKey()`/`mergeKey` (already used for archive matching), MLB's `away|home|localDate` and fights' `org|fighter|fighter|localDate` (both already used by `diffRuns()` for the Updates tab). Sport-prefixed (`football:`/`mlb:`/`fights:`) so the three can't collide in one flat map. `replaySchedule` rows with no correlated parent game (MLB's "recent game" ambiguous-airing rows, fights' matchup-only EPG rows) simply get no `watchKey` and render no checkbox — there's no stable game identity to tick against, same scope limit the catch-up correlation itself already has.
- **Frontend**: one shared `watchToggleHtml(key)` helper (returns `""` when there's no key) renders a real `<input type="checkbox">` under a styled box — visually hidden, not `display:none`, so it stays in the tab order and announces correctly. One delegated `change` listener (`initWatchToggles`) handles every checkbox on the page; toggling one immediately syncs every OTHER checkbox sharing that key (a game can be visible as both a fixture row and a catch-up row at once), then POSTs — and reverts all of them together if the save fails, rather than leaving a checked box that didn't actually persist. `watchedMap` loads from `/api/watched` BEFORE any sport's data renders (the bootstrap awaits it first), so there's no flash of unchecked state on first paint.
- **Placement is deliberately not uniform.** The fight poster card (`renderEvent`) and the catch-up list (`renderCatchUp`) show the toggle right on the row/card, since there's nothing to expand — a catch-up row already names one specific airing. The schedule row (`fixtureRowHtml`) is different: first shipped with the checkbox on the collapsed row itself, but the user pushed back ("I don't want the tick box to show on the live games preview... put it where I click on it and it shows the channels") — a schedule of 15-20 rows a day shouldn't carry a checkbox on every one before you've even looked at it. It now lives inside `.fx-detail`, next to the broadcast info, the same click that reveals the channels. The collapsed row still shows watched state at a glance, though: `.fixture:has(.watch-input:checked) .fx-head { opacity: 0.5 }` dims it even with the checkbox itself hidden until expanded.
  - This is also why the checkbox can't nest inside `.fx-head` — that's a real `<button>` (for native keyboard/expand-collapse semantics), and a checkbox nested inside a button is invalid HTML that double-fires, its own click plus the button's expand/collapse, on every tap. Living in `.fx-detail` sidesteps the problem entirely rather than needing a wrapper element to hold them as siblings.
- Watched rows fade rather than disappear (`:has(.watch-input:checked)`, `opacity` — the schedule and catch-up list stay complete lists so what's left to watch is a glance, not a search), reusing `--zone-primary` (already "good/leading" elsewhere on this page — standings zones) for the checked state rather than a new colour.
- No time-based gating on when the checkbox can be ticked — it's available on upcoming, past and catch-up rows alike, since the user is the only judge of whether they've actually watched something (a live stream of a game the forward window still calls "upcoming", say). Adding a kickoff-passed guard would be complexity for a scenario with no real downside if ignored.

## Login: a real session cookie, not Basic Auth (built 2026-08-20)

Replaced the site-wide HTTP Basic Auth gate with a login page (`public/login.html`) + a signed session cookie. The user: *"why does it ask for login details every time I restart? It's annoying."*

- **Why Basic Auth actually caused this.** A browser's Basic Auth credential cache lives only for the life of the browser *process*, not persisted like a cookie — so it re-prompts on every real restart. That's rare to notice on desktop, but constant on Android, where the OS kills backgrounded browser processes routinely; each reopen is effectively a restart. Chrome's password manager can save Basic Auth credentials, but the native browser-chrome popup doesn't get the same one-tap autofill treatment a real `<form>` login gets, especially on Android — so even a saved credential still meant typing it.
- **Same env vars, no new secret.** `api/login.js` checks the submitted form against the same `BASIC_AUTH_USER`/`BASIC_AUTH_PASSWORD` the dashboard already had. On success it sets `session=<token>` — `HttpOnly; Secure; SameSite=Lax; Max-Age=31536000` (a year, deliberately not a session cookie, since surviving restarts is the entire point). `middleware.js` checks that cookie instead of an `Authorization` header.
- **The cookie's value is an HMAC over the credentials themselves** (`HMAC-SHA256(key = BASIC_AUTH_PASSWORD, message = BASIC_AUTH_USER)`, hex-encoded), not a random per-login session ID — there's no session store to revoke a random ID against, and standing one up (Blob, KV, whatever) would be real infrastructure for a personal single-user tool where the actual threat model doesn't call for it. This still gets automatic revocation for free: change the password in the Vercel dashboard and `sessionToken()` recomputes to a different value, so every existing cookie stops matching instantly. Deliberately no rate-limiting or lockout either — same posture Basic Auth already had.
- **The token function is duplicated, not shared, between `middleware.js` and `api/login.js`, and that's structural, not an oversight.** `middleware.js` runs on Vercel's Edge runtime (a platform requirement for root-level middleware, not a choice); `api/*.js` runs as ordinary Node serverless functions, matching the rest of `api/`. The two can't share a module. Both use only Web Crypto (`crypto.subtle`, global in both Edge and modern Node — no `node:crypto` import), so the exact same function body works unmodified in either file. Verified byte-identical between the two files, and confirmed live in Node: deterministic for the same credentials, and produces a different token the moment the password changes.
- **Distinguishing a real page load from the app's own `fetch()` calls, so a failure degrades the same way Basic Auth's did.** A 401 is still correct for `/data/*.json` and `/api/watched` — they already have their own "failed to load" handling, and redirecting a `fetch()` response would just fail in a more confusing way. Only an actual navigation gets sent to `/login.html`. Checked via `Sec-Fetch-Dest: document` (confirmed against this project's own real traffic — a captured `/api/watched` request showed `sec-fetch-dest: empty`, validating the signal is genuinely present and named as expected in Chrome), with an `Accept: text/html` fallback for any browser that doesn't send Fetch Metadata headers.
- **Open-redirect guarded on both ends.** `/login.html?redirect=<path>` fills a hidden form field so a successful login lands back where you were headed, not always `/`. Both the client (before display) and `api/login.js` (before ever issuing a redirect) reject anything that isn't a same-site path — `//evil.com`, `https://evil.com`, or a missing value all collapse to `/` rather than being trusted.
- **`/login.html`, `/api/login` and `/api/refresh` are the middleware matcher's exclusions.** The first two avoid a redirect loop (the login flow can't be gated behind the auth it's establishing); `/api/refresh` was already excluded for its own `Bearer $CRON_SECRET` check, unrelated to this change.
- Login page design deliberately duplicates a small slice of `index.html`'s own tokens (Oswald/Inter fonts, panel-bg card, floodlight accent button, light/dark via the same `data-theme`/`prefers-color-scheme` pattern) rather than linking a shared stylesheet — one small self-contained page, not worth a build step or a `<link>` to `index.html`'s much larger embedded styles.

## MLB (added — full 30-team schedule, standings, and TV)

Added as a full parallel sport, not a footnote — the page has a top-level sport switcher (`#sportSwitcher` in `public/index.html`) because MLB's volume (~15 games/day across 30 teams) doesn't fit the single-scroll layout the football side uses. Own data file (`public/data/mlb.json`), own build script (`scripts/build-mlb.js`), own npm script (`build-mlb`, also chained into the composite `build-data`).

**Scope**: all 30 teams, no filtering to favorites — daily games (±7 days, same window convention as football), standings (AL/NL, 3 divisions each + wild-card), and **U.S.-only** TV coverage (national + every team's regional network). The official feed also exposes Canadian and Mexican entries for some games; `spike/fetch-mlb.js` explicitly drops Sportsnet, TVA Sports and TV Azteca so MLB stays within the requested U.S. channel scope.

**Data source**: [MLB Stats API](https://statsapi.mlb.com) (`statsapi.mlb.com`) — free, public, unauthenticated, official. Unlike the football pipeline, this is a *single* authoritative source for schedule, live broadcasts, *and* standings — no cross-site name matching, no roster-checking, no fuzzy join. Team reference data (id, division, venue timezone) is hardcoded in `spike/mlb-teams.js` since ballparks don't move mid-season; live broadcast data (national + home + away TV channels, correctly reflecting each season's carrier changes) comes bundled with the schedule endpoint itself — see `spike/fetch-mlb.js`.

**Past games show no score** — a deliberate MLB-specific extension of this doc's existing no-live-scores policy (see "Out of scope" above), not a contradiction of it: past games display teams, original broadcast channel(s), and (where available) replay info, but never the result.

**Replay/rebroadcast tracking** — the reason "past games" needed real investigation rather than just reusing the football section's compact history-row treatment: the user regularly watches games the next day rather than live, so knowing *which channel replays a game and when* matters as much as the original broadcast.
- MLB's own Stats API has no replay field — confirmed by inspecting the raw response.
- The first lead offering a single template across every network (tvinsider.com) explicitly disallows Claude in `robots.txt` — not used, regardless of technical feasibility. **TV Passport (`tvpassport.com`) is the aggregator that worked instead**: fully permissive `robots.txt` (checked live — `User-Agent: *`, empty `Disallow`), one server-rendered listing-page template per station (`/tv-listings/stations/<slug>/<id>`, station ids discoverable via `sitemap.stations.xml`, per-day pages ~2 weeks out), with Gracenote-grade `data-*` attributes per entry: start time, duration, `data-league`, `data-team1`/`data-team2` (exact MLB full names, including 2026's city-less "Athletics"), live/new/repeat flags, stable `listingID`. Cross-validated same-day against the MASN guide: every replay matched to the minute. Implemented in `spike/replays/tvpassport.js`.
- Two tvpassport gotchas, both validated and handled: (1) **times render in a geo-detected timezone** — the page's own timezone `<select>` declares which; the scraper parses that declared zone and converts to UTC (correct wherever the daily job runs; fails loudly if missing, never guesses). (2) **`data-repeat` is not reliable across stations** (NBC-owned RSNs leave overnight re-airs unflagged; SportsNet Pittsburgh flagged one `new`), so replay-vs-original is decided by air time, not flags: only `data-live="1"` is trusted (correct on every live game in a 16-station sweep), and an airing counts as a replay of a game only if it starts **2–72h after that game's start** (the original airs *at* start time, so the 2h floor separates them; 72h keeps "classics" programming from attaching to a current series). Mid-series ambiguity guard in `scripts/build-mlb.js`: if a not-yet-final game of the same matchup also precedes the airing by ≥2h, the listing is withheld — the next daily build attributes it once that game is final.
- **MASN's Programming Guide** (`masnsports.com/programming-guide/` — the real guide, distinct from a simpler marketing schedule page most networks also have) remains the Orioles source and is strictly richer than the aggregator for them: fully permissive `robots.txt`, ~3 weeks of listings, explicit `Live-HD`/`Repeat-HD` tags, and replay entries carry the *original* game's date as a title suffix (e.g. `...MINNESOTA TWINS 0810` = replay of the Aug 10 game) — a direct correlation key, no air-window inference needed. Implemented in `spike/replays/masn.js`. Covers the Orioles only (MASN dropped Nationals coverage in favor of the Nationals' own team-branded channel — confirmed live, no "NATIONALS BASEBALL" entries appear in the guide).
- **Current U.S. coverage: 12 teams with a validated local linear replay source + national.** Orioles (MASN, native guide); via TV Passport: Red Sox (NESN), Cubs (Marquee), Astros (Space City), Dodgers (SportsNet LA), Mets (SNY), Athletics (NBCSCA), Pirates (SportsNet Pittsburgh), Giants (NBCS BA), Phillies (NBCSP), Yankees (YES); plus **White Sox (CHSN)** from CHSN's own official schedule. The national U.S. replay sources are **MLB Network, FS1, FOX, ESPN, TBS and NBCSN**, matched against every team's games. Toronto's Canadian Sportsnet/TVA entries are intentionally excluded. Other clubs' `.TV`/team-app products and national streaming services still appear nowhere as invented catch-up rows: they do not publish a standard linear replay guide.
- TV Passport sources now fetch today plus the next three U.S. broadcast days (Eastern convention), with a polite pause between daily pages. The 2–72h air-window and mid-series ambiguity guard remain in place, so a replay is not attached to the wrong game or called a replay before the game is final. CHSN's own schedule is read separately because it is not in TV Passport's station index.
- The old "only ~10 replays a day" measurement is no longer a useful ceiling: the schedule now includes CHSN and a four-day guide horizon, and the build logs fetched versus attributed airings so a source or correlation problem is visible. The remaining limitation is source availability, not a deliberate omission: app-only MLB.TV, team `.TV`, Peacock, Apple TV and Netflix libraries do not expose a standard IPTV-style replay schedule.
- **Extension point**: `spike/mlb-replay-sources.js` maps team id → scraper (two return shapes documented there) plus a national-source list. Adding a station still means validating it first (robots.txt, real structured listings, deterministic correlation) — for a tvpassport station that's confirming the station page exists and lists the team's games; for anything else (e.g. CHSN) the full MASN-style validation. Do not guess at slugs, ids, or markup without checking.
- Regional networks are **not** a general "watch from anywhere" solution — they're geo-restricted to each team's home market via cable/that network's own app, same as before any of this was built. Replay tracking tells you the channel and time; it doesn't change what the network itself distributes. (For this dashboard's actual user that caveat is informational only — see the multi-market note in the Audience section.)

**Frontend**: `public/index.html`'s `renderEvent()` — the same card renderer football fixtures use — renders MLB games unmodified (MLB games simply don't set the fields, like `rivalry` or bracket-tie context, that make the football-only parts of that function render anything). The one addition is `e.replayGroups`, an optional extra broadcast-group block shown under the normal channel listing when present. MLB games are grouped by date only (`renderMlbGames`) — no country/competition nesting, since it's one league. Standings get their own renderer (`renderMlbStandings`) since baseball's columns (W-L-PCT-GB) don't fit the football table's (P-W-D-L-GD-Pts), but reuse the same `.standings-table` CSS and zone-highlight classes (division leaders + current wild-card qualifiers).

## Boxing & MMA — "Fights" vertical (built 2026-08-11)

Third sport tab (`🥊 Fights`). Scope (expanded at the user's request 2026-08-12): **all UFC events including Dana White's Contender Series**, **PFL**, and **boxing** — marquee cards from BoxingScene plus **EPG-derived cards from live TV listings** (see below; that pair is the answer to "there used to be fight nights every week on TV"). One combined chronological tab, **90-day forward / 14-day back windows**. No results ever — the no-scores policy extends to fight outcomes. Replay tracking shipped with it (see below); on-demand services are now linked as official replay/catalogue checks rather than invented as linear stations.

**Sources — every claim live-validated 2026-08-11 before being built on:**
- **MMA: ESPN's public site API** (`spike/fetch-ufc.js`, serving both league codes `mma/ufc` and `mma/pfl`) — `site.api.espn.com/apis/site/v2/sports/mma/<league>/scoreboard?dates=YYYYMMDD-YYYYMMDD`. Free, unauthenticated JSON, the same single-authoritative-source class as MLB's statsapi; range queries cover past and future. Bouts arrive in ascending billing order with the **main event last** (cross-checked on completed cards of both leagues: the event name carries the last bout's surnames), and bout times cluster into waves — **the latest wave held the headliners on the completed cards checked**, so `mainCardUTC` = latest distinct wave. US broadcast names are live-accurate and league-specific — UFC/DWCS on Paramount+, while **PFL stayed on ESPN + ESPN+ when UFC left** — always taken from the feed, never hardcoded. `geoBroadcasts` is US-only — UK channels can't come from here.
- **Boxing: BoxingScene** (`spike/scrape-boxingscene.js`) — `boxingscene.com/schedule`, robots permissive, no AI-agent blocks. The page is a Next.js RSC stream and only the first few cards exist as plain HTML — but the flight payload embeds a full structured `"event":{...}` object per card (slug, name, `event_date`/`event_time`/`event_timezone`, `venue`, `networks[]`). The scraper decodes the `self.__next_f.push` chunks and brace-matches those objects out — **data objects, not markup**, which is the stable contract. Two site conventions handled: `event_timezone` says "EST" year-round (their label for US-Eastern wall time — mapped DST-aware), and titles use both "A vs. B" and "A-B" forms (dash split only fires when both halves look like full names, so hyphenated surnames can't be cut). Events with no `networks` are skipped — that IS the scope filter. Note the networks list is mixed-market as listed (e.g. "ESPN+, Sky Sports") — the dashboard keeps that row explicitly labelled **Listed by source**, never pretending it is worldwide or US-only. **BoxingScene lists upcoming cards only**, so past boxing cards are carried forward from the previous `fights.json` (that's what makes their replays matchable); UFC past events come straight from the API's date range. **The bare `/schedule` page is a curated top-10** (verified 2026-08-12): per-network sub-pages (`/schedule/dazn`, `/schedule/skysports`, `/schedule/proboxtv`, ...) carry additional cards, so the scraper fetches and merges all of them by slug. It remains a marquee source, not a complete rights database.
- **Global Boxing News schedule** (`spike/scrape-global-boxing.js`) — permitted, server-rendered schedule with UK start times, event pages and explicit `Watch on` links. It adds dated cards with a named broadcaster when BoxingScene misses one, and attaches a **UK** market row plus an official service link when the fighter pair matches. It is explicitly UK-oriented; it is not used to infer worldwide rights.
- **Official Zuffa Boxing distribution** (`spike/scrape-zuffa-boxing.js`) — UFC's country guide publishes event-specific services across the US, Brazil, Canada, Mexico, UK/Ireland, Europe, Asia and other markets. A separate official Paramount announcement supplies promotion-wide US/Canada/Latin America rights, applied only to cards whose own poster/source identifies them as Zuffa Boxing. The resulting rows are market-labelled and clickable; no other promotion inherits them.
- **EPG-derived fight events** (`fetchUkLiveFightListings` / `fetchNaLiveFightListings` in `spike/replays/fight-replays.js`, composed in `build-fights.js`) — the weekly-fight-night answer: for a viewer, what's on IS the schedule, so **live fight listings on the tracked channels become events in their own right**. A listing with a parseable matchup either merges into a known card (same main-event surnames within the 14-day window — its channel joins that card's broadcasts) or becomes a new event; no clean matchup, no event. This covers the promotions **no league feed reaches** — boxing, ONE Championship, BKFC, BKB — with only UFC/PFL/Contender Series excluded, since those already arrive from the ESPN feeds and must not be duplicated. Events are classed into two honest buckets from the listing text alone, `MMA` vs `Boxing`, since listings carry no promotion metadata.
- **Matchup parsing order**: the listing's short line ("Aaron McKenna v Etinosa Oliha"), then the programme title, then — for promotion cards whose short line is just the event's name ("One Fight Night 46") — a `headlined by A v B` extraction from the long blurb, which is how ONE Championship cards get their headline bout. In that last case the short line becomes the event's title. **Gotcha, validated live: tvguide keeps the "Live ..." programme title on REPEAT airings**, so liveness is decided by time, not title — events group by matchup with the EARLIEST airing as the true start, later same-matchup airings fall through to replay correlation, and the known-event merge spans the whole past window so a carried-forward card absorbs this week's "Live"-titled repeats. Proven end-to-end the day it was built: the Sky-only Zuffa Boxing card (McKenna vs Oliha) that BoxingScene missed became an event from its live listing AND had its two Sky Sports Action re-airs matched into the catch-up schedule in the same build. NA side uses TV Passport's real `data-live` flag + boxing show-type markers (structurally safe; activates when a live boxing card airs on those channels). Coverage horizon note: EPG-derived events appear only a few days ahead (the listing pages' reach), so marquee cards come from BoxingScene early and weekly TV cards materialize during the week.
- **MMA breadth: Sherdog** (`spike/scrape-sherdog.js`) — `sherdog.com/events`, robots permissive (`User-agent: *` / `Allow: /`). Every row of the events table is **schema.org microdata** (`itemprop` startDate / name / location on `<tr itemtype=".../Event">`) — a machine-readable contract, not presentation markup. This is what covers the promotions no feed reaches: ONE Championship, Rizin, ACA, LFA, Cage Fury, Brave, Pancrase, Deep, KSW, Cage Warriors, Bellator, BKFC, Glory, Invicta. Two measured limits: **no broadcast data** (cards show "Channel TBC" unless the EPG layer independently finds them airing) and **no start time** (every startDate is midnight UTC — cards show the date and "Time TBC" rather than a fabricated kickoff). **Volume needs a filter, not a firehose**: the page lists ~256 events across ~229 promotions, mostly tiny regional shows with no broadcast anywhere, so `MAJOR_PROMOTIONS` keeps the ones with real broadcast footprints (~28 in a 30-day window) and UFC/PFL/DWCS are excluded outright since the ESPN feeds already supply them *with* bouts and channels.
- **Dedupe across schedule + EPG**: a promotion's card can arrive twice under different product names — Sherdog's "One on Prime Video 46" and the EPG's "One Fight Night 46". Surname matching can't join them (the schedule copy has no announced bout), so they're matched on **promotion word + event number within 36h**, and the EPG copy wins because it carries a channel and a real start time.
- **Ruled out, checked live**: Tapology (robots disallows ClaudeBot + 403), BoxRec (robots disallows /schedule.php + 403), ESPN's HTML pages (robots disallows anthropic-ai — doesn't affect the API host), tvinsider (already out for MLB), radiotimes.com (robots names anthropic-ai), **FightNews** (robots disallows ClaudeBot, serves 403), **Ring Magazine** (robots fully permissive and its `/events` page has broadcaster strings, but the payload carries **no date field at all** — unusable for a schedule), **BoxingNews24** (permissive, and its monthly schedule article has a rich format with UK times and broadcaster, but it was **two weeks stale** when checked — only July entries in mid-August). Fallbacks if a primary breaks: UFC.com/events (server-rendered Drupal); build keeps the previous run's events per-org on fetch failure regardless.
- **Betting sites, assessed 2026-08-12** (the user's suggestion — they do employ large teams logging every event). Verdict: not worth it, on evidence. The ones with the best data **actively block automated access** — bet365 and Sofascore return 403 even for robots.txt, Flashscore names AI crawlers and carries blanket disallows. Of those that permit crawling, **oddsportal and Betfair specifically disallow their event pages** (`*/match-event/*`, `/sport*eventId*`), leaving only oddschecker/William Hill/LiveScore, which are heavily JS-driven with their APIs disallowed. Most decisively, **none of them publish broadcast channels**, which is this dashboard's entire point — a betting-sourced card would land as "Channel TBC" exactly like a Sherdog one, and Sherdog already covers MMA exhaustively for free. Betting odds are also explicitly out of scope (see "Out of scope (v1)"). Revisit only if a permitted source is found that pairs schedules *with* broadcasters.

**"Why aren't there weekly fight nights any more?"** — surveyed empirically 2026-08-12 across a full Friday/Saturday fight weekend, and the answer is that the linear-TV era genuinely ended, not that the pipeline is missing it. **Zero** boxing on ESPN, ESPN2, ESPN Deportes, FS1, Telemundo, TUDN, TSN1/2 or Sportsnet One; the only US/CA fight programming found was CBS Sports Network's UFC replay blocks and Fight Network. Boxing now lives on **streaming** — of the 13 scheduled cards, 8 are DAZN, the rest ProBox TV, Amazon Prime, ESPN+, Sky Sports, even TikTok LIVE — which BoxingScene reports and the dashboard already shows. Corollaries worth not re-litigating:
- **No DAZN channel exists in TV Passport's 19,619-station index** (it's an app, not a linear feed, in these markets), and none on tvguide.co.uk either.
- **FightBox** (`fightbox/32668`) is a real combat channel but carries library/tape content with no parseable matchups ("Bangkok Fight Night", "LNK Boxing Night 13") — it would add noise, not fights. Not scraped.
- Premier Sports 1/2 carried no fight programming; ITV4's "fight" hits are AEW wrestling; 5Action and Sky Sports+ have none.
- The owner's own fight channels (Boxing TV, HBO Boxing, Matchroom Boxing, One Championship TV, BKFC TV, UFC) are 24/7 archive/VOD feeds — their provider's own EPG shows "No information available" or "Streaming on this service" for them, and they appear in no public EPG. They carry library content, not a schedule to track; the dashboard's job for those is telling the owner **which service** has each event so they know which channel to open.

**UK channels** (`ukChannelsFor` in `scripts/build-fights.js`, each entry validated, never assumed):
- **UFC numbered cards + Fight Nights → TNT Sports** — EPG-validated: press reports said Paramount takes UK UFC from January 2026, but TNT Sports 1's own guide lists "Live UFC" in UFC 330's exact prelim/main-card windows plus Countdown/Breakdown shoulder programming. **When press and the EPG disagree, the EPG wins** — re-check if TNT's UFC listings ever disappear.
- **Dana White's Contender Series → no UK entry** — validated the night a DWCS card aired (2026-08-11): TNT's schedule showed padel and cricket in its exact window. No UK linear channel exists to claim.
- **PFL → DAZN** — exclusive UK/Europe rights (press-confirmed 2026-08-12, consistent with PFL's absence from the TNT/Sky EPGs).
- Boxing's confirmed market rows come from Global Boxing News, the official Zuffa guide, or the EPG that actually lists the airing. 5Action and Sky Sports+ were both checked and show no fight programming — not scraped.

**Replays / "Catch up"** — the rock-solid-catch-up requirement, both markets:
- **North America** via the TV Passport layer the MLB scraper already runs on (`spike/replays/tvpassport.js` now exports `scrapeTvpassportListings` as the shared fetch/parse/timezone layer; the MLB wrapper's behavior is unchanged). Stations in `spike/replays/fight-replays.js`: **CBS Sports Network** (airs "UFC Reloaded" full-event replays with `data-league="UFC"` and the event number in the episode title — an exact correlation key) and **Fight Network** (24/7 fight channel; the *Canada* feed `fight-network-canada/3433` is the one with validated listings — the USA feed carried nothing on the check day). **ESPN2 checked and dropped**: its fight programming is gone with the 2026 US rights move.
- **UK** via **tvguide.co.uk** (robots: only `/search` disallowed): server-rendered `/channel/<slug>` pages where every `.js-schedule` row carries `data-date` as an **ISO UTC timestamp** — machine-readable air times, zero timezone parsing. Channels: Sky Sports Action, Sky Sports Main Event, **Sky Sports Mix** (note: slug has no `-hd` suffix, unlike its siblings), TNT Sports 1, TNT Sports 2. No live/repeat flags exist here — "Live" is just title text — which is why correlation uses air-time math, not flags.
- **Gotcha that cost real coverage**: one page is **one broadcast day**, running ~6am to ~6am, so it spills into the *next* calendar date. That makes it look like `?date=D` returns two days, and an early "every other day" fetch pattern therefore skipped whole days silently — which is exactly how a Saturday ONE Championship card went missing. Fetch **consecutive** days; the sweep runs today + 5 days so the coming weekend is always in reach whatever weekday the build runs.
- **Correlation** (`correlateFightAirings` in `scripts/build-fights.js`, exported pure): numbered UFC airings match only the event with that exact number; everything else needs BOTH main-event surnames (diacritic-insensitive) in the airing's title; every match requires the airing to start **6h–14d after the event's own start** (a card runs 4-6h, so 6h excludes the live broadcast; 14d keeps "UFC 222" library re-airs out). Covered by a committed regression test, `spike/test-fight-correlation.js` (`npm run test-fights`), whose airing titles are real strings captured from the four networks' listings — a fresh build day can legitimately match zero airings (validated: CBSSN was re-airing months-old numbered events on build day), so the test is what proves the rules, not build-day luck.

**Pipeline**: `scripts/build-fights.js` → `public/data/fights.json` `{generatedAt, upcoming, recent, replaySchedule}`; npm `build-fights` chained into `build-data`; `fights.json` added to the workflow's commit list. Fetch budget: 2 API calls (ufc, pfl) + 9 BoxingScene pages + Global Boxing News + 2 official UFC/Paramount pages + (2 TV Passport stations × 2 pages) + (5 UK channels × 2 pages) per day — the replay-airing and live-listing reads share one memoized fetch per station/channel per run. Cards carry `source` (the raw event) so the next build can roll past boxing cards forward.

**Imagery** (added 2026-08-12 — the fights cards were the only ones with no graphics): every fight card carries exactly one identity graphic, plus fighter flags.
- **Org marks** (UFC, PFL) come from the ESPN feed's own `leagues[].logos[]` — note that *guessed* CDN paths 404 (`/i/leaguelogos/mma/500/ufc.png`) while the feed's `/i/teamlogos/leagues/500/ufc.png` resolves, so always take the URL from the response. There is **no separate Contender Series league** on ESPN (checked `dwcs`, `contender-series`, `ufc-contender-series` — all 400), so DWCS correctly shows the UFC mark; its own name is already in the event tag line.
- **Fighter country flags** come from each athlete's `flag.href` and fill the normal badge slots — the sport's own convention, and the only fighter imagery available: **this endpoint has no headshots** (athlete objects carry just fullName/displayName/shortName/flag/accolades). ESPN serves a `blank.png` placeholder for fighters with no known nationality (common on Contender Series prospect cards) — dropped to null so the card falls back to a monogram instead of an empty rectangle.
- **Boxing event posters** come from BoxingScene's own `image.thumbnail_300x225_url` (~300×159, ~10-20KB) with its `attribution` credit in the alt text. The art is 16:9 landscape composed around both fighters, so it's displayed **whole and centered at ≤270px** rather than cropped into a full-width strip — and at/below its native width so it stays sharp. Full-size art (640-768px, 50-84KB) exists but isn't worth the repo growth.
- Boxing cards with neither poster nor org (EPG-derived ones) fall back to a 🥊 badge. All images self-host through the existing `cacheImage` (subdirs `orgs`/`flags`/`posters`). Org marks key on the org name and flags on the country code, but **posters deliberately use the default URL content-hash key, not the event slug** — promoters swap a card's artwork when an opponent or co-main changes, and a slug key would mask the new art forever since `cacheImage` returns any existing file for a key. The superseded file just sits unused, which is the cheaper trade. Coverage is currently 13/13 BoxingScene events.
- `scripts/serve.js` gained real image MIME types at the same time — images had been relying on browser content-sniffing as `application/octet-stream`, which the new `.webp` posters made worth fixing so local preview matches Vercel.

**UI**: cards reuse `renderEvent()` — fighters in the team slots (country flags where known, monogram badges otherwise), a prebuilt `e.eventTag` line ("UFC 330 · Xfinity Mobile Arena, Philadelphia · 12-fight card · main card Sun 16 Aug, 02:00 UK") in the matchday-tag slot, UK-only time pill (`kickoffLocal` stays null — venue timezones aren't in the sources, and a fabricated "local" time is worse than none; `renderEvent` hides the local pill when absent). Three-mode toggle (Upcoming / Past / **Catch up**) mirroring MLB's; single column, no sidebar.

**The "Catch up" view (MLB, Fights and Football)** — built at the user's request because per-game replay chips make "what can I watch next" cumbersome: each build also emits a flat `replaySchedule` (one row per airing — airTimeUTC, `endsAtUTC`, UK time, channel, event label, context sublabel), and the shared `renderCatchUp()` renders it **airing-ordered, earliest first, events repeating per re-air**, grouped by UK date. MLB rows label games by their venue-local date ("played Mon 10 Aug") since a Monday-night ET game is Monday's game even when first pitch is past midnight UK.
- **Rows survive until the programme ends, not until it starts** (2026-08-12, the user: "keep them a few hours so I can join in progress"). TV Passport publishes each listing's real slot length via `data-duration`, carried through to `endsAtUTC`; tvguide.co.uk has no duration field, so a 3h (MLB) / 4h (fights) stand-in applies. Anything already under way renders with an "on now" tag.
- **Two classes of row, and the difference is deliberate.** A row whose airing correlates to a tracked event gets that event's name and date. Airings that *can't* be pinned to one are still listed, labelled by matchup alone — because dropping them is what made the view look empty:
  - **MLB**: the mid-series ambiguity guard withholds an airing when a not-yet-final game of the same matchup also precedes it, which is right for a game card but was discarding most of the schedule (measured: 77 airings fetched, 21 attributed). Those now appear as "Boston Red Sox @ Toronto Blue Jays — recent game" with both crests, never attached to a game card. 3 visible rows became 33.
- **Fights**: UK/NA channels re-air plenty of cards no schedule source lists (MVP Boxing, BKFC, Sky's "Fight Night", UFC Reloaded classics). Any airing naming a parseable matchup is listed with the programme as context ("Cherneka Johnson v Dina Thorslund · MVP Boxing"); airings with no matchup — UFC Countdown, The Verdict, The Ultimate Fighter, Ultimate Knockouts compilations — stay out as studio/preview filler. The live broadcast of an already-listed upcoming card is also skipped, since it belongs on that card. Scheduled rows remain airing-ordered; when no EPG replay exists, the Catch up view also lists recent cards with official services to check for on-demand replay and says that availability varies by country/provider.
- Both build scripts log `airings fetched / attributed`, so a silent drop like the MLB one is visible next run.
